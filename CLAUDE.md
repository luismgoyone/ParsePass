# ParsePass: project conventions

ParsePass turns any resume into a clean, ATS-friendly version and shows exactly what an
applicant tracking system reads, before and after. The product spec, ATS rules, milestones and
architecture notes live in `docs/SPEC.md`. Read it before starting feature work.

UI designs live in the Google Stitch project "ParsePass" (Stitch MCP server `stitch`,
project `11086528156520217138`); screenshots are in `docs/mockups/`. Follow the Technical
Parser Minimal design system summarized in `docs/SPEC.md#design`.

## Stack

Next.js 16 (App Router, `src/`), TypeScript strict, pnpm 11, Tailwind v4 + shadcn/ui
(`base-nova` style, `cn` from `@/lib/utils`), unpdf (pdf.js) and mammoth for text extraction,
Anthropic TypeScript SDK (structured outputs) and @google/genai as a free alternative, Zod, @react-pdf/renderer and docx
for export, Upstash Redis for rate limiting, Vitest, Playwright, ESLint + Prettier.

## Folder layout

```
src/app/              routes: / (upload), /diagnostic, /review, /export. API under src/app/api/
src/components/ui/    shadcn/ui primitives (add with `pnpm dlx shadcn@latest add <name>`)
src/components/shell/ site header (step nav), footer
src/components/       feature components by screen (upload/, diagnostic/, review/, export/)
src/lib/ats/          text extraction, ATS view reconstruction, issue checks, scoring (pure)
src/lib/resume/       resume schema (Zod), honesty check, date normalization, templates
src/lib/extraction/   model extraction (server-only): Claude and Gemini behind extractResume()
src/lib/env.ts        read env vars at call time, never at import time
tests/unit/           Vitest (*.test.ts)
tests/fixtures/       resume fixtures (generated by `pnpm fixtures`)
tests/e2e/            Playwright (*.spec.ts)
docs/                 SPEC.md and mockups
```

## Checks

Run lint, typecheck and tests before every commit:

```bash
pnpm lint && pnpm typecheck && pnpm test
pnpm build && pnpm test:e2e   # before opening a PR, or when touching pages or routes
```

- Playwright starts the app on :3100 and records a video of every test (proof videos for PRs).
- Run `pnpm format` before committing.
- CI (`.github/workflows/ci.yml`) runs the same checks. `main` requires them to pass.

## Conventions

- **Honesty is a feature.** Claude only restructures what the user wrote. Never add code paths
  that insert companies, titles, dates, numbers or skills that aren't in the source text.
  Suggestions are always shown for the user to accept, never applied automatically.
- **Privacy.** Store nothing server-side. No database. Never log resume text: log counts,
  token usage and errors only. The Anthropic key stays on the server.
- Never commit secrets. New env vars go in `.env.example` with a comment, and in the README table.
- Build and tests must pass without any env vars. Create clients lazily and don't read env at
  module top level.
- Keep ATS logic pure and in `src/lib/ats/` so it runs in the browser, on the server and in
  Vitest. Add a fixture and a unit test for every new issue rule.
- UI follows the tokens in `src/app/globals.css` (dark only). Use semantic classes
  (`bg-panel`, `bg-card`, `bg-console`, `text-muted-foreground`, `text-subtle-foreground`,
  `text-success`, `text-warning`, `text-destructive`) instead of raw colors. Severity is always
  a label + color, never color alone. Parser output, rule IDs and file names use `font-mono`.
- Server components by default. Add `"use client"` only where interactivity requires it.
- Small commits with clear, conventional messages (`feat:`, `fix:`, `chore:`, `docs:`, `ci:`).
- Work on a branch and open a PR with `gh pr create`. Never push directly to `main`.
  PRs are squash-merged using the PR title, so write PR titles as commit messages.

## Repo settings

`repo.config.json` holds the GitHub description, homepage and topics. `pnpm sync-repo`
(`scripts/sync-repo.sh`) applies those plus the merge settings and branch protection.
It is safe to re-run.

**Rule:** whenever `docs/SPEC.md` changes in a way that affects the repo description or
topics, update `repo.config.json` and run `pnpm sync-repo` in the same PR.
